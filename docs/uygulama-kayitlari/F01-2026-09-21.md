## Ne ve neden hazırlandı?

Mevcut dirty/untracked çalışma ağacı korunarak kaynaklar gerçek `.env`, `.git`, cookie ve eski build çıktıları olmadan `/tmp` altındaki kontrollü kopyaya alındı. Derleme ve HTTP kontrolleri bu kopyada yapıldı. Yerel PostgreSQL 16 üzerinde yalnızca `devcoreblog_f01_test` adlı geçici veritabanı ve sentetik içerik kullanıldı.

Tekrar kullanılabilir üç doğrulama var:

- [Tek komutluk izole çalıştırıcı](../../scripts/verification/run_f01_baseline.sh)
- [Güvenli sentetik PostgreSQL fixture'ı](../../scripts/verification/f01_fixture.sql)
- [Standart kütüphaneli HTTP kontrolü](../../scripts/verification/f01_http_baseline.py)
- [Süre sınırlı EF migration keşfi](../../scripts/verification/f01_migration_probe.py)

Çalıştırıcı test sonunda uygulamayı ve PostgreSQL'i durdurur, test klasörünü varsayılan olarak siler. `DEVCORE_F01_KEEP_TEMP=1` yalnızca teşhis gerektiğinde sentetik klasörü tutar. Fixture, hedef DB adı tam olarak `devcoreblog_f01_test` değilse çalışmayı reddeder.

## Derleme kanıtı

İlk temiz restore denemesi kısıtlı ağ ortamında “projeler belirleniyor” aşamasında ilerlemedi ve kontrollü olarak durduruldu. Global NuGet cache'de gerekli tam sürümler mevcut olduğu doğrulandı. Kullanıcının restore metadatası yalnızca geçici kopyaya alındı ve şu kaynak derlemesi çalıştırıldı:

```sh
dotnet build DevCoreBlog.csproj --no-restore --nologo \
  --disable-build-servers -m:1 -p:NuGetAudit=false -nodeReuse:false
```

Sonuç: Web, Core, Data ve Services derlendi; **0 uyarı, 0 hata**, 4,48 saniye. Bu kaynak derlemesi temiz package restore veya dependency advisory kontrolü sayılmaz; o kanıt F55'te tamamlanacak.

## Veri izolasyonu ve fixture

Geçici küme `/tmp/devcoreblog-f01.*` altında, 127.0.0.1:55432 üzerinde başlatıldı. Sandbox paylaşımlı belleğe izin vermediği için yalnızca bu sentetik küme çalıştırması ortamın onaylı sandbox-dışı mekanizmasıyla yapıldı. Gerçek PostgreSQL, Cloudinary ve `.env` kullanılmadı.

Fixture şu örnekleri içerir: geçmişte yayınlı, gelecekte yayınlı, taslak, pasif yazı, pasif kategori, ham Markdown script işareti, Türkçe karakterler, uzun içerik ve aynı başlıklı kayıt. Elle oluşturulan fixture şeması migration testi değildir.

## Başlangıç HTTP bulguları

`scripts/verification/run_f01_baseline.sh` sıfır çıkış koduyla çalıştı. `/post/f01-visible` işareti önce görülmeden testler başlamadı.

| Kontrol | HTTP sonucu | Başlangıç bulgusu |
|---|---:|---|
| Parola config'i yokken sadece `f01-admin` kullanıcı adıyla login | Son sayfa 200 `/Admin/Dashboard` | **Yeniden üretildi** — F02 |
| Gelecek tarihli yayınlı yazının detayı | 200 | **Yeniden üretildi** — F17 |
| Ham Markdown `<script>` işareti | 200 ve script elementi response içinde | **Yeniden üretildi** — F04 |

Tokenless toggle yalnızca test DB'sindeki 2001 numaralı sentetik yazıyı değiştirdi. Uygulama logunda bu işlemde bütün Post kolonlarını güncelleyen SQL de görüldü; F21/F22 bulgusuyla uyumlu başlangıç kanıtıdır.

## Migration keşfi

Süre sınırlı probe, hem `--project DevCoreBlog.Data/...` hem `--project DevCoreBlog.csproj` ile tamamlandı. İkisi de `ApplicationDbContext` türünü buldu, EF tool/runtime patch uyarısını verdi ve **“No migrations were found.”** döndürdü. Gerçek migration dosyaları Web ağacında mevcut olsa da EF keşfi onları listelemiyor. Şema bu nedenle migration ile değil, açıkça manual fixture ile kuruldu. Düzeltme F10'a bırakıldı.
