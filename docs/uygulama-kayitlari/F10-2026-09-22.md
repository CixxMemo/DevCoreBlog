## Ne ve neden değişti?

`ApplicationDbContext` Data projesinde, beş mevcut migration ise Web projesindeydi. Npgsql varsayılan olarak context assembly'sinde migration aradığı için araç `No migrations were found` sonucu üretiyordu. `Program.cs`, migration assembly'sini çalışan Web assembly'si olarak açıkça yapılandıracak şekilde düzeltildi. Migration dosyaları taşınmadı, silinmedi, yeniden üretilmedi ve beş geçmiş migration kimliği değişmedi.

Microsoft EF runtime, Design, Tools ve kurulu `dotnet-ef` aynı `10.0.10` patch seviyesine getirildi. Npgsql provider `10.0.3` olarak korundu; paketin yerel metadata'sındaki destek aralığı EF Core `>=10.0.4` ve `<11.0.0` olduğundan seçilen sürüm bu aralığın içindedir. Gereksiz major/minor yükseltme veya yeni paket eklenmedi.

Doğrulama akışı artık doğru Web proje yollarıyla beş migration'ı listeler, idempotent kurulum SQL'i üretir ve iki ayrı geçici PostgreSQL veritabanında sınar. Boş veritabanı üretilen SQL ile kurulur. Eski veritabanı gerçek `InitialCreate` migration'ına getirilir, biri yayınlı biri taslak iki sentetik kayıt eklenir ve kalan dört migration uygulanır.

Eski zincirin veri davranışı raporlandı: ilk migration'daki `IsPublished` alanı ikinci migration'da `IsActive` adını alır; son migration yeni `IsPublished` alanını varsayılan `false` ile ekler. Bu nedenle eski yayınlı örnek aktif kalır fakat otomatik yeniden yayımlanmaz. Eski taslak örnek pasif ve yayımlanmamış kalır. İki satır da korunur; geçmiş migration değiştirilerek farklı bir sonuç dayatılmadı.

## Değişen dosyalar

- `Program.cs`: Npgsql yapılandırmasına Web migration assembly'si açıkça bağlandı.
- `DevCoreBlog.Data/DevCoreBlog.Data.csproj`: EF runtime `10.0.10` patch sürümüne hizalandı.
- `scripts/verification/f01_migration_probe.py`: doğru Web projesinde beş migration'ın sıralı keşfi ve sürüm uyarısının yokluğu zorunlu hale getirildi.
- `scripts/verification/f10_database_migration_probe.py`: idempotent SQL, boş DB kurulumu, eski DB yükseltmesi ve veri dönüşüm raporu eklendi.
- `scripts/verification/run_f01_baseline.sh`: iki geçici F10 veritabanı ve migration doğrulaması birleşik regresyon koşusuna katıldı.
- `README.md`: gerçek csproj yolları ile migration listeleme ve idempotent SQL üretme komutları yazıldı; production update sınırı belirtildi.
- `Migrations/*`: içerik ve kimlikler incelendi; hiçbir migration dosyası değiştirilmedi.

## Kurallara uyum

- **Mevcut yığın ve proje sınırı:** Dört proje korundu. Context Data'da, geçmiş migration'lar Web'de kalmaya devam eder; bu ayrım composition root'ta açık yapılandırıldı.
- **SOLID ve sadelik:** Migration konumu tek Npgsql configuration noktasında tanımlandı. Yeni context, design-time factory, repository katmanı veya paralel migration geçmişi oluşturulmadı.
- **Veri güvenliği:** Beş geçmiş migration değiştirilmedi. Empty ve legacy testleri ayrı DB'lerde çalıştı. Forward SQL'de `DROP TABLE` bulunmadı ve eski örnek satır sayısı/değerleri raporlandı.
- **Paket disiplini:** Yalnızca Microsoft EF patch farkı hizalandı; Npgsql'ın doğrulanmış uyum aralığı korundu. Major/minor upgrade yapılmadı.
- **Faz dışı kontrol:** Schema iş kuralları, yeni constraint'ler, production migration, form davranışı ve F11 kapsamı değiştirilmedi.

## Veri ve geri dönüş

- Repository migration geçmişi ve uygulama şeması değişmedi; yeni migration eklenmedi.
- Production veritabanına bağlantı kurulmadı ve `database update` çalıştırılmadı.
- F10 değişiklikleri geri alınırsa context tekrar Data assembly'sinde migration arar; CLI beş geçmiş migration'ı göremez ve deploy migration akışı bozulur.
- Gerçek deployment öncesi güncel yedek, hedef bağlantı doğrulaması, üretilen SQL incelemesi ve forward-fix planı gerekir. Destructive Down otomatik çalıştırılmaz.
- Eski zincirin `IsPublished → IsActive` dönüşümüne müdahale edilmedi. Gerçek eski veriler için otomatik yayın kararı verilmedi; test sonucu güvenli varsayılanın yayımlanmamış olduğunu kanıtladı.
